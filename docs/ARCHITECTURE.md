# 설계와 예외 처리

## 책임 분리

`paintcore`는 Qt Core/Gui만 사용하고 창·대화상자를 알지 못합니다. `paintui`가 Canvas와 MainWindow를 소유하고, 실행 대상 `retropaint`가 앱 생명주기를 담당합니다. Qt Network, WebEngine, 외부 프로세스 실행 의존성을 추가하지 않았습니다.

편집의 기본 단위는 `State`입니다. 문서 크기, 배경색, 같은 크기의 ARGB32 premultiplied 이미지 레이어, 활성 레이어를 포함합니다. `Document::commit`은 후보 상태를 검증하고 Undo 자료를 만든 다음 현재 상태를 교체합니다. 후보 상태를 만드는 동안 실패하거나 작업을 취소하면 이전에 확정한 문서를 보존합니다.

그리기·선택·텍스트는 Canvas가 임시 상태로 표시하고 확정할 때 문서에 반영합니다. QImage의 공유 복사로 불필요한 초기 복사를 줄이되, 쓰기가 시작되면 해당 이미지가 분리됩니다. 운영체제가 프로세스를 강제 종료하는 메모리 고갈까지 C++ 예외 처리로 복구할 수 있다는 보장은 하지 않습니다.

## 변경 기록

- 픽셀 편집은 변경된 영역의 이전/이후 이미지 조각을 기록합니다. 비교는 행 단위이며 현재는 변경된 레이어 전체를 스캔합니다.
- 크기·레이어 수·이름·표시 상태 등 구조 변경은 이전/이후 상태를 보관합니다. QImage는 가능할 때 버퍼를 공유합니다.
- 저장 상태는 이력 위치가 아니라 고유 revision ID로 판별합니다. 저장 후 Undo하고 다른 그림을 그려도 잘못 '저장됨'으로 표시하지 않습니다.
- 기본 이력 예산은 256 MiB입니다. 초과하면 오래된 항목을 지우지만 마지막 한 항목은 남깁니다. 따라서 큰 구조 변경 하나가 예산을 초과할 수 있습니다.
- 이력 바이트 수는 이미지 데이터의 보수적 합계입니다. 객체·할당기·렌더링·파일 인코딩 메모리를 포함하는 프로세스 RSS가 아닙니다.

## 자원 한도

| 항목 | 현재 한도 |
| --- | --- |
| 한 변 | 1~32,768픽셀 |
| 한 이미지 | 32 × 1024 × 1024픽셀, 내부 버퍼 최대 128 MiB |
| 문서의 레이어 합계 | 64 × 1024 × 1024픽셀, 내부 버퍼 합계 최대 256 MiB |
| 레이어 | 최대 16개; 픽셀 합계 한도도 동시에 적용 |
| 이미지/프로젝트 입력 파일 | 최대 300 MiB |
| 프로젝트 내부 PNG 1개 | 최대 140 MiB, 디코딩 한도 128 MiB |
| 레이어 이름 | QString 256단위, 파일 UTF-8 1,024바이트 이하 |

크기 변경은 레이어 전체를 할당하기 전에 합계 한도를 확인합니다. 프로젝트는 길이 값을 읽은 뒤 한도와 남은 파일 바이트를 검사합니다. 일반 이미지는 PNG/JPEG/BMP/GIF 헤더만 허용한 뒤 해당 디코더를 지정합니다. 자동 회전은 JPEG 등의 이미지 메타데이터를 따릅니다.

최대 크기의 문서, 변경 기록, 작업 중 복사본, 합성 화면, 인코딩 버퍼가 동시에 존재할 수 있습니다. 따라서 256 MiB 문서 한도는 앱 전체 256 MiB 한도가 아닙니다. 더 큰 이미지/많은 레이어를 지원하려면 타일 저장소와 타일 단위 이력으로 바꾸는 작업을 우선 검토해야 합니다.

## 실패 처리

| 상황 | 처리 |
| --- | --- |
| 손상/잘린 프로젝트, 비정상 크기·길이 | 현재 문서를 바꾸기 전에 파싱 실패 |
| 지원하지 않는 이미지 | 허용된 래스터 형식의 헤더가 아니면 거부 |
| 선택/붙여넣기 취소 | 임시 상태 폐기; 확정 문서 유지 |
| 채우기 취소 | 작업 스레드에 취소 플래그 전달; 후보 이미지를 커밋하지 않음 |
| 그리기 중 마우스 소유권 상실 | 스프레이 타이머와 임시 획 취소 |
| 저장 중 쓰기 실패 | QSaveFile로 임시 파일에 저장, 직접 덮어쓰기 우회 금지, 성공 시에만 교체 |
| 확장자를 자동으로 붙인 경로가 이미 존재 | 최종 파일 이름에 대해 다시 덮어쓰기 확인 |
| 저장 취소/종료 취소 | 창과 수정 상태 유지; 명시적인 Discard만 버리기로 처리 |
| 다층 문서 또는 숨긴 단일 레이어를 일반 이미지로 저장하려 함 | `.rpaint` 저장 또는 별도 이미지 내보내기로 안내 |
| 복구 사본이 손상됨 | 이전 사본을 보존하고 덮어쓰는 자동 복구 저장을 중지 |
| 복구 사본을 열지 않음 | 시각 접미사를 붙인 별도 파일로 보관한 뒤 새 작업 시작 |
| 같은 앱의 동시 실행 | 로컬 파일 잠금으로 두 번째 인스턴스 차단 |

저장은 QSaveFile의 교체 동작을 사용하는 파일시스템 범위에서 원자적입니다. 전원 차단, 디스크 하드웨어 손상, 특수/네트워크 파일시스템의 모든 동작을 보장하는 것은 아닙니다. 프로그램은 네트워크 경로를 찾아보거나 원격 파일을 다운로드하지 않지만, 사용자가 OS에 마운트한 네트워크 드라이브를 파일 대화상자에서 선택하면 파일 접근 자체는 OS의 동작입니다.

복구 사본은 Qt AppLocalDataLocation의 `recovery.rpaint`에 30초 간격으로 저장합니다. 저장 중인 확정 revision에만 적용되므로 아직 확정하지 않은 선택/문자/획과 마지막 30초 이내 변경은 복구되지 않을 수 있습니다. 정상적인 저장·종료에서 정리하고, 복구를 거절한 사본은 `recovery.rpaint.<UTC시각>`으로 남깁니다.

## 구현 중 수정한 사항

투명 선택을 확정만 해도 픽셀이 바뀌는 문제, 자유 선택 경계를 시작/끝점만으로 계산하는 문제, 가운데 버튼 이동의 잘못된 커밋, 한쪽 캔버스 가장자리에서 양쪽 크기가 바뀌는 문제를 수정했습니다. 레이어 변경 전에 붙여넣기를 확정하고, 마우스 해제 위치를 마지막 편집 위치에 반영합니다.

화면 격자와 투명 체크무늬는 실제 다시 그릴 범위만 순회합니다. 합성 화면은 문서 revision으로 캐시하므로 줌만 바꿀 때 다시 합성하지 않습니다. 불필요한 이미지 크기 검증용 할당을 없앴고, Undo에 저장하던 작업 이름은 메뉴에서 실제 사용합니다. 메모리·성능 측정은 VERIFICATION.md를 참고하세요.

## 후속 우선순위

1. macOS Apple Silicon/Intel, Windows에서 네이티브 빌드와 입력·클립보드·HiDPI·파일 대화상자·장시간 편집 검증.
2. Qt 런타임과 정확한 라이선스/소스 묶음, macOS 서명·공증, Windows 서명, 깨끗한 OS에서 오프라인 설치 검증.
3. 네이티브 한글 IME 조합 중 단축키, 대용량 이미지, 디스크 용량 부족·권한 변경·강제 종료 복구의 OS별 점검.
4. 실제 문서 작업에서 병목이 확인되면 변경 영역 추적/타일 이력과 비동기 파일 저장 도입. 현재 작은 도구마다 추상 계층을 추가하지 않음.

현재 범위에 포함하지 않은 기능: 인쇄/스캐너, HEIC/WebP/PSD, 애니메이션 편집, 벡터 객체 재편집, 임의 각도 회전 UI, 압력 감지 브러시, 마스크·혼합 모드·레이어 불투명도, 무한 캔버스. 최신 그림판의 모든 기능과 1:1 동등하다고 주장하지 않습니다.
