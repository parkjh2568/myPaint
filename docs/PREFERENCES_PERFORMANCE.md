# 설정 전환 성능 점검

## 변경 사항

- 지우개 방식/색상 변경은 다음 획에 사용할 값과 해당 컨트롤만 즉시 갱신합니다. 문서 픽셀은 바꾸지 않습니다.
- 이 변경에서 테마·밀도 속성 재적용, 전체 캔버스 그리기 예약, 모든 도구 컨트롤 동기화를 제거했습니다. 기존 구현은 이 작업을 매번 수행했습니다.
- 같은 전경색·색상환 hue·크기의 컬러휠은 재래스터하지 않습니다. 색상 또는 크기가 바뀌면 다시 그립니다. 이는 지우개뿐 아니라 크기/불투명도 슬라이더와 반복 화면 동기화의 불필요한 작업도 줄입니다.
- 설정 저장 실패 시 세션에만 적용된다는 기존 안내와 작업 중 변경 금지를 유지합니다.

## 검증

실제 `main.ts` 메서드를 계측된 DOM/Canvas 경계로 실행하는 Node 회귀 검사:

- 지우개 모드 100회 변경: 전체 문서 렌더 예약/테마 재적용 0회, 설정 저장 100회.
- 동일 색상환 100회 동기화: 실제 페인트 1회. 색상·hue·크기 변경은 무효화됨.
- Node 348개, TypeScript, Vite 빌드, 포맷 검사 통과.

이는 불필요한 작업 횟수 검증이며, 실제 사용자 클릭 지연의 밀리초 수치나 Windows/macOS 속도 보증이 아닙니다. Chromium UI 검사는 실행 환경의 socket 권한 오류로 시작하지 못했습니다.

## 남은 실기기 확인

1. 큰 이미지/여러 레이어를 열고 투명/배경색을 반복 전환한 직후 획을 그립니다.
2. 두 모드 모두 선택한 활성 레이어에 적용되고 Undo/Redo 및 PNG 알파가 유지되는지 확인합니다.
3. 컬러휠에서 검정·회색 상태의 hue 변경과 리사이즈, 색상 변경이 바로 표시되는지 확인합니다.
4. DevTools Performance로 입력 지연·긴 작업·메모리를 측정합니다. 여러 이미지 탭 추가 후 메모리 사용은 별도로 재확인해야 합니다.
