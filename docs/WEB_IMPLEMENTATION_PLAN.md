## 구현 범위와 보존할 계약

첫 구현 범위는 데스크톱 브라우저의 그림 도구·선택·문자·레이어·Undo/Redo, 로컬 이미지와 `.rpaint` 열기, 프로젝트 다운로드, 이미지 내보내기, 브라우저 복구다. 그림판 아이콘은 재사용하고 툴팁·접근성 이름을 유지한다. 모바일 전체 기능, PWA 설치·오프라인 재시작, 클라우드 저장, 원격 이미지, 압력 감지는 별도 후속 범위다.

- `paintcore`는 Qt Core/Gui만 사용한다. Widgets와 브라우저 API는 UI·플랫폼 경계에 둔다.
- 실패·취소는 문서, revision, Undo/Redo, 미확정 선택·문자, 기존 정상 파일·복구 사본을 훼손하지 않는다.
- 네이티브 저장의 QSaveFile direct-write fallback 금지와 prepare→파일 commit→install 순서를 유지한다.
- 웹 다운로드 요청을 외부 디스크 저장 성공으로 처리하지 않는다. 브라우저 복구 성공도 다운로드 성공과 구별한다.
- `.rpaint` v1 형식과 레이어·픽셀 의미를 유지한다. 웹 한도 초과 파일은 기존 문서를 보존한 채 거부한다.
- 순차 작업은 소유 함수 안에 둔다. 여러 경로의 공통 의미 또는 지속되는 작업·버퍼·콜백의 수명 관리가 있을 때만 분리한다.
- C++은 기존 4칸·명명·clang-format, CMake와 YAML은 기존 2칸 예외를 따른다. 변경된 계약의 주석·문서와 완료된 TODO를 함께 정리한다.

## WB00 기준 상태와 게시 대상 조사

현재 myPaint와 홈페이지는 각 origin/main을 추적한다. myPaint는 이전 개선분이 미커밋 상태이고 홈페이지는 깨끗하다. 기존 변경을 보존하고 구현 전 소스 diff·상태·홈페이지 해시를 기록한다. 폴더 이동 전 절대 경로가 남은 CMake 캐시는 보존하고 새 빌드 폴더에서 구성한다.

홈페이지 로컬 workflow는 main push·root 전체 게시를 정의한다. 원격 최신화·권한 정비는 로컬 웹 빌드의 선행 조건이 아니다. 빌드는 네트워크 Git 동기화를 실행하지 않고 대상 폴더·기존 사용자 수정만 확인한다.

산출물은 소스 기준 기록과 게시 위치 결정이다. 코드 작업 브랜치는 기존 작업을 확인한 뒤 `codex/` 접두사를 기본으로 사용한다. 원격 커밋·push와 staging 변경은 하지 않는다.

## WB01 SDK와 예외 처리 이식시험

**전체 UI 변경 전에 통과해야 하는 기술 시험이다.** 이전 검토의 Qt 6.12 예외·이벤트 루프 조건을 출발점으로 삼고, SDK 선정 시 해당 버전 문서를 다시 확인한다. 예외 지원 Qt 소스 빌드, 호스트 Qt 도구, 대응 Emscripten과 컴파일·링크 설정을 함께 고정한다. 기본 Qt 바이너리에 앱 플래그만 더하는 구성을 채택하지 않는다. [Qt WebAssembly](https://doc.qt.io/qt-6/wasm.html)

시험은 작은 Widgets 창, QPainter 입력, State·Document의 편집과 Undo/Redo, 한글 표시, 비동기 오류창, 잘못된 크기 검증 예외와 오류 후 다음 획까지 포함한다. 실제 브라우저의 입력·타이머 콜백에서 확인한다. 테스트 실행 파일 생성만으로 대체하지 않는다.

처음에는 스레드·격리용 Service Worker 없이 실행한다. 기본 지원 경로에 Asyncify/JSPI나 SharedArrayBuffer를 요구하지 않는다. 긴 연산은 WB05에서 해결한다.

산출물은 툴체인 버전·Qt configure 옵션·빌드 로그·브라우저 버전·예외 회복 결과·초기 크기와 시작 시간이다. 실패하면 SDK를 재평가하고, 해결되지 않으면 HTML UI/별도 코어 경로의 비용을 비교한다. 실패한 설정 위에 전체 이식을 쌓지 않는다.

## WB02 빌드와 앱 생명주기

네이티브 이름·링크·설치·Qt 최소 버전은 유지한다. Emscripten 분기에서 Qt의 웹 실행 대상과 HTML·JS·Wasm 로더를 구성한다. `build-web/`와 `dist/web/`를 사용하고 네이티브 install·runtime 수집을 섞지 않는다. 브라우저 테스트는 네이티브 CTest와 구분된 실행 방식을 정의한다.

`main.cpp`의 시작·스타일·팔레트는 가능한 한 같은 소유 흐름에서 재사용한다. 웹 앱·창은 main 반환 뒤에도 유효한 수명을 갖게 하고 예외 지원 구성의 진입점을 사용한다. 별도 main 파일은 실제로 수명·빌드 분리가 단순해지는 경우에만 둔다. Qt 창 생성 전 오류는 HTML 시작 화면에서도 표시한다.

웹 창 생성 시 네이티브 QStandardPaths·QLockFile·복구 worker를 시작하지 않는다. 브라우저 저장소 초기화 뒤 WB07을 연결한다. 웹 QLockFile을 탭 간 공유 잠금으로 사용하지 않는다.

브라우저 연동은 `src/webplatform.*`와 `web/browser.js` 같은 작은 경계를 후보로 둔다. JS는 File·Blob·IndexedDB·DOM 자원을, C++은 Qt 객체와 콜백 소유권을 담당한다. 실제 연결 방식에 따라 합칠 수 있다. Document에 DOM 코드를 넣거나 여러 서비스 계층으로 감싸지 않는다.

완료 검증은 main 반환 뒤 입력 지속, 오류 후 편집, 중복 초기화 방지, 컨테이너 resize, 로더 실패와 WebGL 컨텍스트 손실 처리다. 네이티브 CTest·offscreen smoke도 통과해야 한다.

## WB03 제한된 공통 바이트 입출력

경로 API는 유지하고 QIODevice 기반 읽기·쓰기를 공유한다. `readProject(QIODevice&)`, `writeProject(State, QIODevice&, cancel)` 같은 overload를 검토하되 정확한 시그니처는 기존 API·취소 계약에 맞춘다. 네이티브 래퍼가 파일 검사와 QSaveFile 생성·commit을 계속 소유한다.

헤더·치수·레이어 합계·길이·UTF-8·PNG 검증은 한 구현에서 수행한다. 웹 입력이라고 무제한 디코더나 형식 탐지 우회를 사용하지 않는다. 장치의 seek 지원 계약을 명시하고 웹은 크기가 검증된 seek 가능한 버퍼를 사용한다.

출력은 최종 QByteArray 크기의 사후 검사만으로 제한하지 않는다. 인코더 write/seek 시 한도 초과 증가를 거부하는 장치 등으로 버퍼를 제한한다. 이는 실제 자원 경계를 위한 분리이며 각 write 문장을 헬퍼화하는 작업과 다르다. 실패한 버퍼·파일은 설치하지 않는다.

시험은 파일→버퍼→파일의 레이어·픽셀·메타데이터 왕복, 짧은 쓰기·읽기 실패, 잘린 레코드, 길이 위조, 잘못된 UTF-8, PNG 실패, 출력 상한이다. 서로 다른 Qt/코덱의 PNG 압축 바이트 동일성을 계약으로 만들지 않는다. 기존 파일 보존·취소·할당 실패 시험을 유지한다.

## WB04 비동기 명령과 대화상자

### 작업 소유권과 수명

창이 소유하는 작은 전면 작업 상태에 요청 번호, 문서 세션/세대, 시작 revision·active, 종류·취소 상태를 기록한다. 문서 교체·취소·새 요청에서 이전 작업을 무효화한다. revision만으로 pending·active 변화를 판정하지 않는다. 첫 구현은 snapshot 준비부터 완료까지 편집을 막고 취소만 허용하는 단순한 정책을 사용한다.

MainWindow의 QAction 차단만으로 충분하지 않다. 마우스·키보드·IME·붙여넣기·drop·레이어·메뉴를 함께 제어한다. 스프레이·진행 중 제스처를 확인하고 IME commit 뒤 조합이 남으면 시작하지 않는다. 인코딩의 즉시 취소와 “취소 요청 후 현재 호출 종료 대기”를 UI에서 구별한다.

비동기 함수 반환 시 QScopedValueRollback은 종료된다. busy 해제는 실제 성공·실패·취소 종료 지점에서 한 번 처리한다. 지연 콜백에는 스택 dialog·bool·State의 참조를 남기지 않는다. QObject parent/context, QPointer 또는 작업 소유 타입으로 수명을 관리한다. C++ 예외는 JS 경계를 넘어 전파하지 않고 각 완료 콜백 안에서 처리한다.

PreparedEdit은 네이티브의 이벤트 없는 commit/install 구간에 사용한다. 파일 선택·다운로드·IndexedDB 콜백을 기다리는 동안 유효한 편집 트랜잭션으로 보관하지 않는다.

### 사용자 명령의 후속 동작

색상·글꼴·기울이기·레이어 이름·크기·도움말·오류·복구 선택까지 웹에서 반환값을 기다리지 않는 대화상자로 바꾼다. 완료 콜백에서 선택값을 검증한 후 편집을 실행한다. 동일 작업·종료 확인창의 중복 생성을 막는다.

새 그림·열기의 기존 문서 대체에는 “프로젝트 다운로드”, “버리고 계속”, “취소”를 제공한다. 다운로드는 기존 문서를 유지하고 요청 직후 자동 전환하지 않는다. 사용자가 파일을 확인한 뒤 명시적으로 버리고 계속하도록 한다. 실제 저장을 알 수 없는 상태를 저장 완료로 표현하지 않는다.

탭 닫기·새로고침은 Qt closeEvent와 같은 계약으로 가정하지 않는다. 앱 안의 문서 대체는 제어하되 브라우저 종료는 사전 복구와 가능한 기본 이탈 안내로 보완한다. 끝내기 메뉴가 임의로 탭을 닫을 수 있다고 약속하지 않는다.

선택·문자·곡선·다각형 pending에서 대화상자/작업 취소, 창 소멸, 요청 중복, 다른 문서의 늦은 결과, 오류 후 다음 편집을 시험한다. 네이티브 maybeSave·save의 bool 계약을 웹 때문에 일괄 교체하지 않는다.

## WB05 웹 작업 한도와 긴 연산

웹의 입력 바이트·이미지 픽셀·레이어 합계·치수·이력·출력 한도를 한 곳에 정의한다. 빌드 대상별 정책으로 충분한지 먼저 판단하고 불필요한 런타임 설정 계층을 만들지 않는다. 파일 형식과 앱 작업 한도를 구별하며 같은 v1 형식의 지원 부분집합으로 설명한다.

File.size 외에 코어도 디코딩 전에 검사한다. 붙여넣기·새 문서·resize·회전/기울이기·선택 확장·레이어 추가·합성·PNG 출력 전에 한도를 적용한다. 치수 곱셈·바이트 합계의 범위를 할당 전에 검사하고 후보·합성·이력·인코딩·JS 전달 버퍼가 겹치는 비용도 포함한다. 프런트엔드 검사만으로 안전하다고 보지 않는다. 고정 “32M/64M” 오류 메시지도 실제 정책과 일치시킨다.

채우기는 현재 Document::flood의 span 탐색·후보 이미지를 지속 상태로 소유하는 방식을 검토한다. 일정량 처리 후 반환하고 성공 시 한 번 commit한다. pause/resume에 필요한 실제 작업 단위만 분리하고 픽셀 대입·좌표 계산을 별도 헬퍼화하지 않는다. 네이티브와 복제 알고리즘이 생기지 않게 결과를 비교한다.

합성·prepare의 전체 픽셀 비교·decode/encode는 별도 측정한다. 타이머에 넣어도 호출 중에는 동기식이다. 예산 초과 시 지원 한도 조정 또는 독립 Worker를 선택한다. Worker는 바이트 전달·추가 메모리·모듈 시작·오류·취소를 작은 시험으로 확인한다. 주 스레드 future/join 대기를 해결책으로 사용하지 않는다. [Emscripten 주 스레드 대기](https://emscripten.org/docs/porting/pthreads.html#blocking-on-the-main-browser-thread)

표본은 800×600, 1920×1080의 1·4레이어와 지원 후보 상한 문서다. 기기·브라우저·스케일·이미지 내용을 기록한다. **초기 목표 제안**은 일반 입력 p95 50ms 이내, 분할 구간 약 8ms, 단일 동기 작업의 250ms 초과 입력 정지 제거다. 달성 기록이 아니며 WB01/WB05에서 지원 범위와 함께 확정한다. 기준 초과 해상도를 지원 목록에 그대로 남기지 않는다.

## WB06 파일 열기와 다운로드 UX

열기·사진 삽입·drop의 File 객체는 같은 입력 경계로 전달한다. File.size를 읽기 전 검사하고 읽은 바이트도 재검사한다. Qt 내용 열기 콜백만 쓰면 전체 읽기 뒤 앱 검사이므로 대용량 사전 검사를 생략하지 않는다. 그림을 서버·URL로 전송하지 않는다. [Qt 파일 내용 열기](https://doc.qt.io/qt-6/qfiledialog.html#getOpenFileContent)

완전히 검증된 후보를 준비한 후 WB04의 대체 선택을 거친다. 기존 문서와 입력 후보가 공존하는 메모리도 예산에 넣는다. 파일명은 표시·다운로드 제안값이며 네이티브 경로로 신뢰하지 않는다. 기존 형식 계약과 내용 검증을 유지한다.

프로젝트 다운로드는 레이어를, 이미지 내보내기는 합성 결과를 보존한다. pending 후보 실패·IME 미완료에서는 문서를 바꾸지 않는다. 다운로드 요청 뒤에도 doc.path·saved revision·pending·Redo를 바꾸지 않는다. 요청한 revision 같은 표시용 값을 저장 성공 판정에 쓰지 않는다. [Qt 파일 내용 저장](https://doc.qt.io/qt-6/qfiledialog.html#saveFileContent)

비동기 준비 뒤 브라우저 다운로드 정책에 걸리면 “파일 받기”를 다시 누르는 흐름을 사용한다. Blob/Object URL·전달 버퍼는 적절한 시점에 해제하고 반복 내보내기의 메모리 증가를 확인한다. PNG 투명, JPEG/BMP 배경 합성, GIF 첫 프레임 읽기를 유지한다.

시험은 파일 선택 취소, 빈/손상/초과 파일, 읽기 취소, 다른 요청의 늦은 완료, 이름·확장자, 인코딩 실패, 다운로드 차단, 반복 요청이다. 관찰할 수 없는 OS 다운로드 취소는 저장 성공으로 판정하지 않는다.

## WB07 영속 복구와 다중 탭

첫 후보는 IndexedDB에 검증된 rpaint 바이트와 metadata를 직접 저장하는 경로다. IDBFS 영속화와 동시에 구현하지 않는다. SDK 제약으로 IDBFS를 고르면 동기화 완료·오류와 사본 보존을 같은 시험으로 입증한다. 메모리 QSaveFile 교체만으로 영속화 성공을 표시하지 않는다.

초기화가 끝나기 전 복구 타이머를 시작하지 않는다. 앱·스키마·탭 세션·문서 세션별 키를 두고 새 문서·열기에서 문서 세대를 바꾼다. 복구 후 새 런타임 revision과 옛 실행의 숫자가 같다고 동일 상태로 추정하지 않는다. 같은 origin의 다른 앱과 키를 공유하지 않되 키 이름을 보안 격리로 설명하지 않는다.

한 개의 복구 작업으로 직렬화한다. 직전 정상 snapshot·새 snapshot·현재 head를 관리하고 새 바이트와 head를 같은 저장 트랜잭션에서 확정하는 방식을 우선 검토한다. 개별 요청 성공만으로 완료 표시하지 않고 전체 완료·abort·오류를 처리한다. quota·저장 실패 시 정상 head·사본을 유지한다. 브라우저 정책·디스크 내구성까지 보장하는 문구는 쓰지 않는다.

**복구 완료는 전면 편집 작업과 다른 기준으로 처리한다.** 다른 문서·세대, 취소, 더 최신 snapshot으로 대체된 결과는 폐기한다. 같은 문서에서 편집이 계속되어 revision이 달라지면 이전 시점의 유효 snapshot을 복구본으로 남길 수 있다. 현재 내용까지 보호했다고 표시하지 않고 해당 시각을 표시하며 다음 snapshot을 예약한다. 복구 결과로 화면 문서·Undo·pending을 설치하지 않는다.

이 기준은 연속 편집에서 완료 결과를 모두 버려 복구가 계속 미뤄지는 문제를 줄인다. 순서는 Undo 후 낮아질 수 있는 revision 대소 대신 요청 순서로 판정한다. 작업 직렬화와 head 갱신 검증으로 과거 결과의 덮어쓰기를 방지한다.

첫 범위가 확정 문서만 저장하면 미확정 문자·선택은 복구됐다고 표시하지 않는다. “복구 사본: 시각”, “이후 변경 있음”, “복구 저장 불가”를 구분한다. 다운로드 요청만으로 사본을 지우지 않는다. 명시적 버리기의 보관/삭제는 해당 문서 세션에만 적용한다.

다른 탭 사본을 덮어쓰지 않는다. 발견한 사본은 시각·크기·이름으로 선택하게 하고 손상·거절 시 원본을 보존한다. 유지 개수·총 바이트 상한을 두고 정리는 사용자 선택 또는 새 정상 사본 확정 뒤 수행한다. 반복 탭·복구 거절로 무제한 누적되지 않게 한다.

시험은 재로딩, 연속 편집, Undo/Redo 중 저장 순서, quota·권한·private 모드, transaction abort, 다중 탭, 새 문서 직후 과거 완료, 손상 head·이전 정상 사본, 저장소 삭제, 스키마 차이다. 파괴적 시험은 별도 테스트 origin/프로필에서 한다.

## WB08 입력과 화면 사용성

클립보드는 문자/이미지 편집을 구분한다. 권한·제스처 실패 전에 삭제·cut이 일어나지 않게 하고 전달 성공을 알 수 없는 경로의 보장을 명시한다. 비동기 paste가 다른 문서·레이어·문자 편집기로 들어가지 않게 소유권을 확인한다.

IME 조합 중 도구 변경·다운로드·Enter/Esc·포커스 이동을 실제 OS/브라우저에서 시험한다. 조합 키를 확정 명령으로 오인하지 않는다. offscreen commit 이벤트와 실제 IME 검증을 구별한다. 시스템 글꼴 목록을 동일하게 재현한다고 약속하지 않고 대체 글꼴·필요한 로컬 배포 자산을 확인한다.

마우스 소유 버튼, pointer 상실·탭 비활성화의 획/스프레이 취소, 스크롤·확대·DPR·오른쪽 메뉴 충돌을 확인한다. 문서 밖 선택 핸들과 키보드 포커스도 접근 가능해야 한다. touch는 페이지 스크롤과 그리기 충돌을 확인한 뒤 지원한다.

좁은 창은 레이어·옵션을 접고 핵심 도구·색·Undo/Redo를 유지한다. 접근성 이름·선택 상태·키보드 도구/대화상자 접근을 제공한다. 브라우저 종료·새로고침 단축키를 무조건 가로채지 않는다.

## WB10 결과물 수집과 홈페이지 폴더 반영

웹 빌드와 검증이 성공하면 기존 형제 홈페이지 저장소의 mypaint 폴더에 산출물을 반영한다. 기본 위치는 프로젝트 위치에서 계산하며 이동 전 절대 경로를 하드코딩하지 않는다. 명시적 대상 설정도 저장소 root가 아닌 앱 하위인지 검사한다.

준비 중인 결과는 소스 저장소 안에서 완성하고, 실패한 빌드 결과를 홈페이지에 쓰지 않는다. 허용 파일과 해시·로더 참조를 검증한 후 반영한다. 대상의 수동 수정·staged 변경·심볼릭 링크·출처 불명 파일과 경로 탈출을 검사한다. 삭제는 앱이 소유한다고 확인한 이전 산출물에만 한정한다. 복사 실패의 보존·복원 경계도 시험한다.

index·css·js·img·workflow 등 앱 폴더 밖 파일과 다른 작업·staging을 보존한다. 전체 홈페이지가 깨끗해야만 빌드하도록 강제하지 않는다. 자동 fetch·pull·add·commit·push·인증 설정 변경은 하지 않는다. Git 상태를 읽는 검사는 허용하되 수정하지 않는다.

산출물은 HTML·CSS·JS·Wasm·실제 로컬 자산·고지·manifest다. SDK·소스맵·네이티브 앱·secret·사용자 파일은 제외한다. 소스 상태·툴체인·해시를 기록한다. 게시 자격 증명이나 별도 체크아웃은 필요하지 않다.

임시 두 폴더에서 정상 반영, 홈페이지 파일·staging 보존, 대상 수동 변경 거부, 누락·손상 산출물, 경로 탈출, 복사 실패·중복 실행을 시험한다. 실제 홈페이지에는 검증된 웹 결과만 반영한다. 사용자 커밋·push 이후에는 WB11을 수행한다.

## WB11 실제 Pages 인수와 문서

실제 하위 경로의 새 방문·직접 접속·재로딩·기존 캐시를 확인한다. 로더·JS·Wasm·폰트의 버전과 상대 경로, MIME·실제 응답 헤더·보안 컨텍스트를 확인한다. 다른 호스팅 통과로 Pages 인수를 대체하지 않는다.

버전별 로더·자산 참조와 이전 HTML 방문자의 자산 보존 정책을 정한다. 해시 파일만 만들고 Qt 로더 내부 참조의 정합성을 추정하지 않는다. 앱·홈페이지 Service Worker가 있다면 범위·캐시 간섭을 확인한다.

실 URL의 프로젝트 왕복·내보내기·클립보드 거절 대안·복구를 시험한다. 되돌리기는 앱 폴더만 이전 산출물로 복원하는 새 커밋으로 수행한다. 홈페이지 전체 reset·강제 push를 하지 않는다. 이전 버전이 새 복구 스키마를 못 읽으면 보존·안내하고 파괴적 변환을 하지 않는다.

README·ARCHITECTURE·FILE_FORMAT·VERIFICATION·NOTICE에 지원 범위·저장 의미·한도·복구 제한·게시/되돌리기를 반영한다. 구현 시 AGENTS의 Widgets 규칙은 웹 UI도 포함하는 UI 경계로, 네트워크 금지는 웹 대상의 동일 사이트 정적 앱 자산 로딩만 허용하는 범위로 명확히 한다. 데스크톱·코어 경계는 유지한다.

주석은 각 변경에 병행한다. 비동기 이후 잘못된 스택 수명, “반환 시 저장 완료”, “잠금 하나로 모든 탭 보호”, 완료 TODO, 잘못된 한도·플랫폼 설명을 제거한다. 후보 설치·복구 확정·콜백 수명처럼 오해하기 쉬운 이유만 짧게 남긴다.

## 구현 단위와 진행 판정

권장 단위는 기준/SDK 시험, 웹 빌드·시작, 공통 입출력, 비동기 명령, 한도·긴 연산, 웹 파일, 복구, 입력·UX, 게시 도구, 실호스팅·문서 순서다. 관련 시험·설명을 각 단위에 포함하고 미사용 인터페이스만 먼저 추가하지 않는다. WB09는 모든 단위에 병행한다.

첫 실제 작업은 **WB00 소스 기준 확인과 WB01 이식시험**이다. 시험 통과 전 전체 대화상자 전환·자동 게시를 시작하지 않는다. 취소·과거 콜백·복구 실패·원격 충돌에서 상태 보존을 입증하지 못한 단위는 다음 기능의 완료 근거로 삼지 않는다.

실제 구현 결과는 별도 기록하며 계획상의 완료 조건을 실행 증거와 구분한다. 커밋·push는 홈페이지 폴더에서 별도로 수행한다.

## 2026-11-03 구현 반영

WB00~WB08의 제품 코드와 로컬 패키징·안전 반영 도구를 구현했다. 실제 Chrome 검증, 네이티브 회귀, 성능 측정과 반영 증거는 WEB_IMPLEMENTATION_RESULTS.md에 기록한다. 측정 후 웹 레이어 합계는 최초 후보 8 Mi 픽셀에서 6 Mi 픽셀로 낮췄고 동기 PNG는 무압축으로 저장한다. 한도 내 코덱 호출은 동기 실행이며 즉시 취소를 제공한다고 표시하지 않는다.

`.github/workflows/web.yml`은 비용이 큰 동일 버전 Qt 호스트/웹 소스 빌드와 브라우저 검사를 workflow_dispatch로 제공한다. 기존 네이티브 CI는 유지한다. 이 로컬 작업에서 원격 workflow를 실행했다고 주장하지 않는다. WB11의 실제 Pages 인수는 사용자의 홈페이지 commit·push 뒤 수행해야 하며 Safari·Firefox·OS IME 인수도 남아 있다.
