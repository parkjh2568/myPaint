# Classic 98 스킨 정리

2026-11-11. 사용자 첨부 Windows 98 그림판 화면과 [98.css 디자인 시스템](https://jdan.github.io/98.css/)을 참고한 CSS 전용 변경이다.

## 변경 범위

- 회색 표면, 흰색/진회색의 1px 이중 입체 테두리, 눌린 도구의 체크 패턴을 적용했다.
- 기존 문서 제목 영역과 대화상자 제목을 파란 캡션으로 꾸몄다. 새 제목 표시줄이나 가짜 창 제어 버튼을 추가하지 않았다.
- 입력란, 색상표, 레이어 목록과 상태 영역에 오목한 테두리를 적용했다. 슬라이더·체크박스·스크롤바·비활성 버튼·키보드 포커스도 Classic 98에 맞췄다.
- 모바일 패널의 둥근 모서리를 없앴다. 기존 반응형 배치와 터치 타깃 크기는 유지한다.
- 색상표는 누름/키보드 포커스 중에도 실제 그리기 색을 표시한다. 캔버스 크기 조절용 투명 히트 영역은 버튼 배경을 그리지 않는다.
- 강제 색상 모드에서 입력 테두리, 체크박스, 슬라이더와 레이어 선택 표시가 남도록 시스템 색상을 사용한다.

제품 변경은 `web-app/src/style.css`의 Classic 98 범위뿐이다. DOM, 도구 순서, 그리드, 색상표 값, Studio Dark, 엔진, 저장·복구, 패키지 의존성을 바꾸지 않았다. 외부 CSS/글꼴/스크립트를 가져오지 않는다.

## 검증

- Prettier 전체 검사, TypeScript 검사, Vite 프로덕션 빌드 통과.
- Node 테스트 337개 통과: 기존 332개 + CSS 범위·투명 핸들·팔레트·비활성 필드·강제 색상 정적 검사 5개.
- 배포 스테이징/빌드 Python 테스트 44개 통과.
- `git diff --check`, 브라우저 검사 스크립트 문법 검사 통과.
- 독립 정적 리뷰에서 발견한 색상표 누름 상태, 흰색/검정 포커스, 비활성 입력과 강제 색상 선택자 우선순위를 보완했다.

정적 CSS 검사는 실제 렌더링을 대체하지 않는다. `tests/browser.mjs`에는 스킨 전환 시 배치·도구 순서, 투명 핸들, Space를 누른 색상표의 실제 색과 포커스, 강제 색상 입력란 검사를 추가했다. **이번 환경에서는 브라우저 실행/로컬 미리보기 접근 제한으로 이 브라우저 검사와 화면 캡처를 실행하지 못했다.** 실제 Windows/macOS, 모바일 WebView의 렌더링도 미검증이다.

브라우저 실행이 가능한 환경에서는 다음으로 기존 전체 브라우저 검사를 재실행한다.

```sh
npm --prefix web-app ci
npm --prefix web-app run dev
# 다른 터미널
npm --prefix web-app run test:browser
```

환경설정에서 Classic 98을 선택하여 데스크톱, 390px 모바일, 터치 밀도, 대화상자와 스킨 재전환을 눈으로 확인해야 한다. 이 기록 작성 당시에는 원격 푸시·배포 전이었다. 2026-11-12 현재 `style/win98-paint-skin` 원격 브랜치에 코드는 반영됐으며 공개 배포·OS별 화면 인수는 별개다.
