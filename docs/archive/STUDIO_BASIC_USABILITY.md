# 기본 조작·종료·붙여넣기 개선

2026-11-06. [실행·소스·산출물 근거](../evidence/studio-basic-usability.json). 사용자가 별도로 요청한 사용성 작업을 반영했다. 기존 전체 목표는 일시 중지 상태로 유지하며 성능 최적화 루프를 재개하지 않았다. 설치형은 Windows/macOS, 모바일·태블릿은 웹 범위를 유지한다.

## 반영한 동작

| 항목 | 동작과 보호 조건 |
| --- | --- |
| 종료·문서 교체 확인 | 콤보박스 대신 저장 / 저장하지 않고 버리기 / 취소를 직접 선택한다. 저장 버튼에 초기 포커스를 두며 Esc는 취소다. 저장 실패·저장 위치 선택 취소 때 문서와 pending·Redo를 유지한다. 새 그림·다른 파일 열기에도 같은 확인 경로를 쓴다. 웹에서는 프로젝트 다운로드 후 현재 그림을 유지한다. |
| 직접 붙여넣기 | Ctrl/Cmd+V 기본 붙여넣기를 허용하고 paste 이벤트에서 이미지 File을 동기적으로 확보한다. 별도 async clipboard.read를 재호출하지 않는다. PNG 표현을 우선하며 기존 파일 디코딩·삽입 경로를 재사용한다. 텍스트 입력칸과 IME·모달·진행 중 조작은 보호한다. |
| 캔버스 가장자리 조절 | 오른쪽·아래쪽·오른쪽 아래 핸들을 제공한다. 핸들은 문서 바깥에 배치해 작은 그림의 픽셀을 가리지 않는다. 드래그 중 경계·치수만 표시하고 놓으면 기존 geometry Worker에서 한 번 적용한다. 그림을 늘리지 않고 영역만 확장·축소하며 한 번 Undo/Redo로 복원한다. |
| 취소·한도 | Esc·포인터 취소·창 전환 시 resize preview만 취소하고 기존 미확정 문자·선택을 유지한다. 축·레이어 합계 한도를 preview에서 검사하고 초과한 크기는 적용하지 않는다. 처리 실패·취소·문서 세대 변경은 후보를 채택하지 않는다. 원래 크기로 돌아오면 작업·이력 생성 없이 끝난다. |
| 추가 편의성 | 방향키로 핸들 1px, Shift로10px 조절·Enter로 정확한 크기 대화상자를 연다. 캔버스 크기에는 불필요한 보간 옵션을 제거하고 이미지 크기에는 유지한다. 화면 이동 후 삽입 그림을 보이는 위치에 배치하고 크기 한도를 검사한다. 도움말 창에 실제 사용법을 표시한다. 불가능한 선택/레이어 동작을 비활성화하며 도구 커서와 브러시 크기 표시를 제공한다. |

기존 main.ts와 style.css 안의 UI 소유권을 유지했다. 생산 helper 메서드·모듈·의존성을 추가하지 않았으며 engine/document·operations·format 및 codec/Worker/Rust는 직전 기준과 같다. 기존 editDocument에 화면 맞춤 여부를 선택하는 인자만 추가해 드래그 시 줌·원점을 유지한다. 최종 웹은9파일·301,653B이며 입력126개와 전수 SHA를 대조했다. 새 앱 frontend8개도 웹의 공통8개와 같다.

## 실제 검증

| 검증 | 결과 |
| --- | --- |
| 새 공개 사용성 회귀 | 19개 통과. 직접 버튼·추가 clipboard read 없음·중복 삽입 방지·잘못된 이미지 재시도·문자 포커스·다층 RGBA/hiddenRGB·축소/확장·NoOp·Esc/pointercancel/blur·Worker 실패/Redo/retry·소수 줌/DPR2·키보드·모바일 Classic98 버튼 배치 |
| 기존 회귀 | Node327, 웹48, native IPC 모형16, pending36, clipboard4, bulk16, pointer26체크 통과. 기존 원본·pending·Redo·payload 검사는 유지하고 변경한 UI의 제목·직접 버튼 선택자만 맞췄다. |
| 빌드·정적 검사 | 타입·Prettier·정적 웹·macOS 앱 빌드 통과. 마지막 입력 목록 갱신 뒤에도 시험한 payload9개의 SHA가 동일함을 확인했다. |
| 실제 macOS | 새 바이너리 b005cf5dcd51의 저장·복구/코덱/종료/scene4분기 통과. 실제 종료 검사에서 select 없음·직접 버튼3개와 취소·중복 종료·pending/dirty/busy 보존을 확인했다. |

최초 실사용 검사에서 작은 캔버스의 핸들 겹침과 문자 편집창에 가려진 핸들을 찾아 각각 바깥 배치·쌓임 순서로 고쳤다. 대화상자 전환을 기다리지 않던 새 검사와 모바일의 숨겨진 상단 버튼을 누르던 검사는 실제 UI 경로에 맞춰 고쳤다. 옛 종료창 제목을 기다리던 pending 검사도 수정했다. 별도 전체180초 실행기는 실패 기록으로 보존했고, 마지막 단일 명령은36개 통과 후 정상 종료했다. 앱의 코덱20초 제한과 native watchdog120초는 그대로다.

macOS는 LaunchServices wait 완료와 각 성공 marker를 검사한 결과다. launcherExitCode0과 앱 자체 종료 코드 미관측(null)을 구분한다. 시험용 legacy2파일의 bytes/metadata가 같고 임시 root와 작업 소유 서버·앱이 정리됐음을 확인했다. 두 저장소의 Git index/config도 같다. 커밋·푸시·홈페이지 복사·게시를 수행하지 않았다.

클립보드 payload 이벤트와 쓰기 실패는 테스트 모형이다. OS 클립보드의 권한·형식 전달, Windows와 Android 실기기 검증은 별도로 남는다. 실제 macOS 종료 검사는3버튼/취소의 native 통합 근거이며 OS 파일 선택기·쓰기 실패 행렬 전체를 실행한 것은 아니다. 웹 탭 닫기 경고는 브라우저가 제어하며, 메뉴 버튼의 async 붙여넣기에는 브라우저 권한 UI가 남을 수 있다.

재현은 web-app에서 `npm run test:usability`, 기존 `test:browser`, `test:native-persistence`, `test:pending-contract`, `test:clipboard-contract`, `test:bulk-edit`, `test:pointer-contract`를 실행한다. 로컬 URL/브라우저/출력은 각 테스트의 PAINT 환경변수를 사용한다. 새 사용성 검사는 기존 웹 CI에 연결했다. 원격 CI 실행·공개 배포 완료를 뜻하지 않는다.
