# 메뉴와 여러 그림 탭

- 상단 메뉴를 열면 **파일 / 편집 / 이미지 / 레이어 / 설정 / 도움말** 범주를 선택합니다. 테마와 글꼴, 문서 바탕은 설정에 있습니다.
- **열기**와 **새 그림**은 현재 그림을 지우지 않고 새 탭을 만듭니다. 사진 삽입은 현재 탭에 추가합니다.
- 탭을 클릭해 전환합니다. 각 그림의 레이어, Undo/Redo, 확대·이동, 저장 대상은 독립적입니다. 대상 탭 활성화가 성공하면 미확정 선택·문자를 이전 탭에 확정하고, 그 탭의 새 revision을 복구 대기열에 넣습니다. 활성화 실패 시 미확정 편집과 기존 Redo를 보존합니다.
- 웹 파일 선택기는 여러 파일을 한 번에 선택할 수 있습니다. 앱에서는 열기를 반복해 여러 탭을 엽니다.
- 현재 탭에서 프로젝트 저장/이미지 내보내기를 실행합니다. 프로젝트는 `.rpaint`, 이미지 저장은 내보내기를 사용합니다. 웹은 다운로드이며 실제 파일 보관을 확인해야 합니다.
- 탭의 ×로 닫습니다. 편집된 그림은 이름과 함께 저장/버리기/취소를 묻습니다. 비활성 탭의 확인·저장·닫기는 현재 탭을 전환하거나 미확정 편집을 확정하지 않습니다. 설치형은 활성 탭을 닫을 때 다음 탭 활성화와 저장 경로 해제를 함께 처리하고, 비활성 탭은 현재 세대를 유지하며 해당 키만 해제합니다. 기존 복구 파일은 파일 → 복구 사본에서 다시 열 수 있습니다.
- 앱 종료 시 탭을 순회해 활성화하지 않고 각 탭의 변경을 확인합니다. 취소·저장 창 취소·저장 실패·종료 IPC 실패 시 아직 저장하지 않은 편집과 Redo를 유지합니다. 사용자가 명시적으로 저장에 성공한 탭의 저장 결과는 유지합니다. 웹 종료 시 변경된 탭이 있으면 브라우저 경고를 요청합니다.
- 최대 12탭. 새 탭을 열 때 보존 픽셀·이력과 입력 픽셀 합계 512 MiB 한도를 검사합니다. 마지막 탭을 닫아 빈 탭으로 바꿀 때는 닫는 문서의 메모리를 계산에서 뺍니다. 이후 편집에는 문서별 자원 제한이 적용됩니다.
- 복구 쓰기는 비동기이며 30초마다 아직 복구되지 않은 열린 탭을 다시 확인합니다. 앱이 쓰기 완료 전에 강제 종료되면 마지막으로 완료된 사본까지 복구할 수 있습니다. 재시작 후 파일 → 복구 사본에서 그림 단위로 엽니다.

## 검증

`node --import tsx --test tests/document-tabs.test.ts`는 문서별 픽셀·이력·뷰, 활성화 실패 보존, 비활성 탭 복구와 재시도, 닫기 실패·마지막 탭 교체, 범주 분류를 검사합니다.

`npm run test:document-tabs`는 브라우저에서 네이티브 IPC를 모델링해 탭별 경로, 미확정 문자에서 생성된 복구 픽셀, 실패한 닫기, 닫기 후 바인딩 해제와 복구 사본 보존을 검사합니다.

`npm run test:close-cancel`은 실제 Chromium UI의 웹·네이티브 IPC 모형에서 14개 경로를 검사합니다. 닫기·종료 취소, 저장 창 취소·저장 실패, 비활성 탭 저장 후 닫기, 종료 IPC 실패, 비활성 프로젝트로 내보내기 거부 및 정상 경로 재시도를 확인합니다. 미확정 문자의 내보내기 미리보기 픽셀과 실제 Redo 결과를 비교합니다. OS 파일 선택기와 실제 WebView 검증은 별도입니다.

Rust persistence 테스트는 문서 key별 바인딩, 64회 이상 열기·닫기, 실패한 활성화, 비활성 탭의 복구, 닫힌 탭의 늦은 쓰기 거부를 확인합니다. 지원 OS의 실제 패키지와 파일 대화상자 검수는 별도입니다.
